A shared LLM wiki for many agents and git projects is designed here as a seven-part architecture, since no single product covers the brief today. Markdown in git stays the source of truth, with one repo per space and pages in an OKF v0.2 profile that adds claim-level citations and evidence-driven trust, while Wikipedia-style flat pages and typed topic hubs handle cross-cutting subjects. Trust comes from source-pinned evidence that a different agent verifies, never from popularity, and working memory lives in task folders that reach the wiki only through sourced proposals. The recommended platform is Forgejo, obsidian-hybrid-search and Obsidian or Hatchdoor for humans, plus a thin gateway to be written for identity, routing and the write gate. For the first part, 35 Obsidian MCP candidates were narrowed to 15 and scored, and the top pick is [MCP Connector by istefox](https://github.com/istefox/obsidian-mcp-connector), the most-downloaded maintained option in the Obsidian community store.

- Turnkey two-week pilots are ai-memory (MIT, but a read-only web UI) or KiwiFS (BSL, best integrated UI), both on OKF pages so the content carries over to the assembled build.
- Phase 0 is a schema-checked git repo that agents edit on a clone, which is useful within days.
- For Obsidian MCP, pair the istefox connector (write, graph and lint) with a dedicated search server, since obsidian-hybrid-search is the strongest retriever but is read-only.
- The most-starred server, mcp-obsidian, is close to unmaintained and has an open path-traversal issue, so avoid it.
